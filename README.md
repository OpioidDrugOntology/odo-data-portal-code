# ODO Data Portal Code  

Python workflows supporting the curation, annotation, and processing of datasets used to construct the Opioid Drug Ontology Data Portal (ODO-DP).

The repository contains the data curation and processing workflows used to generate the ODO-DP dataset described in the accompanying publication. Workflows include manual curation from the scientific literature, ChEMBL data retrieval and processing, compound annotation from standardized chemical structures, and aggregation of QikProp physicochemical descriptors.

---

## 🚀 Quickstart  

Clone the repository and create the Conda environment.

```bash
git clone https://github.com/OpioidDrugOntology/odo-data-portal-code.git
cd odo-data-portal-code

conda env create -f environment.yml
conda activate odo-chem
```

Each workflow contains:

- Python scripts
- demonstration input files
- demonstration output files
- workflow-specific documentation

Refer to the README within each workflow directory for execution instructions.

## 🔌 API Requirements

Most workflows in this repository run entirely locally. However, the `manual_curation_workflow/assay_description_standardization` workflow uses the Anthropic Python SDK to access Claude models for generating standardized assay descriptions.

Before running this workflow, obtain an Anthropic API key and configure it as an environment variable.

**macOS / Linux**

```bash
export ANTHROPIC_API_KEY="your_api_key_here"
```

**Windows (Command Prompt)**

```cmd
set ANTHROPIC_API_KEY=your_api_key_here
```

**Windows (PowerShell)**

```powershell
$env:ANTHROPIC_API_KEY="your_api_key_here"
```

The API key is not included with this repository and must be obtained separately from Anthropic.

# 🔬 Workflow Overview

The workflows are largely modular and may be executed independently depending on the source data and desired processing step. Where applicable, workflow-specific README files describe any required upstream inputs or downstream processing steps.

## 1. Manual Curation Workflow

This workflow supports curation of bioactivity data extracted from scientific publications identified through PubMed.

Components include:

- Publication table extraction
- Assay description standardization
- ASCII normalization

**Result**

Publication-derived assay records suitable for integration into ODO-DP.

---

## 2. ChEMBL Curation Workflow

This workflow processes bioactivity data obtained from ChEMBL.

Components include:

- Retrieval of document metadata through the ChEMBL API
  - DOI
  - PubMed ID
  - Patent ID
- Reference prioritization
- Aggregation of redundant activity records using defined experimental matching criteria

**Result**

Curated ChEMBL-derived bioactivity records suitable for integration into ODO-DP.

---

## 3. Compound Processing Workflow

This workflow generates chemical identifiers, external database annotations, and calculated molecular properties from **canonical SMILES** produced by the upstream **Chemical Standardization Workflow**. 

The compound annotation workflow includes:

- Generation of Standard InChI
- Generation of Standard InChIKey
- Retrieval of PubChem Compound IDs (CIDs)
- Retrieval of IUPAC names from PubChem
- Calculation of molecular formula
- Calculation of molecular weight
- Generation of additional molecular descriptors where applicable

**Result**

Compound records enriched with standardized chemical identifiers, external database annotations, and calculated molecular properties suitable for downstream integration into ODO-DP.

---

## 4. QikProp Aggregation Workflow

This workflow calculates representative median values for physicochemical descriptors generated by the Schrödinger QikProp module. Descriptor values from multiple QikProp calculations are grouped by canonical SMILES to generate one representative descriptor set per unique compound.

**Result**

Median values for selected QikProp physicochemical descriptors (dipole, SASA, FISA, donorHB, accptHB, QPlogPw, QPlogPo/w, and QPlogS) calculated for each unique canonical SMILES.

---

## 5. UniProt ID Retrieval

This workflow retrieves UniProt identifiers for protein targets using protein names and corresponding taxonomy identifiers. Taxonomy information is used together with the protein name to support organism-specific target matching and assignment of the appropriate UniProt identifier.

**Result**

Protein target records annotated with corresponding UniProt identifiers for downstream integration into ODO-DP.
